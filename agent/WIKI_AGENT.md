# Agent Specification: Wiki synthesis updator (Wiki Agent)

## 1. 職責範圍
當新增論文 PDF、更新 `notes/*.md` 或重新建置網站時，負責同步更新 `wiki/synthesis.md`（`wiki/index.md` 由 `scripts/check_wiki.py` 自動生成與維護）。
- `notes/*.md`：單篇論文的完整結構化筆記（MetaData、摘要、方法、實驗、限制、省思）。
- `wiki/index.md`：知識庫總索引，由 `scripts/check_wiki.py` 根據 `notes/*.md` 自動產出。
- `wiki/synthesis.md`：跨篇脈絡彙整，包含主線演進、方法與目標差異、新手教學順序，以及侷限性與防過度宣稱提醒。

## 2. 更新流程
1. **盤點變更**：檢視 `notes/` 中新增或更新的 `.md` 檔案（例如 `2019-reimers-sbert.md`、`2021-gao-simcse.md`、`2023-zou-repe.md`、`2024-arditi-refusal.md`、`2024-behnamghader-llm2vec.md`、`2023-cunningham-sae.md`）。
2. **更新 `wiki/synthesis.md`**：
   - 在「主線演進脈絡」補入或調整銜接段落與轉折說明。
   - 在「跨篇方法與目標差異」更新比較列。
   - 在「新手教學講解順序」確認講解先後與學習重點是否合理。
   - 在「侷限性與防過度宣稱提醒」補齊該篇的限制與邊界條件。
3. **執行確定性驗證與索引生成**：執行 `scripts/check_wiki.py`，自動更新 `wiki/index.md` 並驗證引用、覆蓋率與格式。

## 3. 撰寫與溯源規則
- **嚴格忠於來源**：只使用 `notes/*.md` 已記載的資訊，不自行推測實驗數字或宣稱未驗證的效果。
- **強制標註來源**：`wiki/synthesis.md` 的每個要點、轉折或比較列都必須附上 `[檔名.md]`（多篇來源可並列如 `[2024-behnamghader-llm2vec.md][2023-zou-repe.md]`）。
- **維持分工清晰**：避免把單篇細節整篇搬進 `synthesis.md`，重點放在跨篇關聯與脈絡。

## `synthesis.md` 撰寫要點
撰寫或更新 `wiki/synthesis.md` 時，應圍繞「跨篇關聯」而非單篇摘要重述，並遵守以下要點：
1. **主線演進脈絡（問題驅動）**：以由淺入深的段落串起各篇脈絡，每段交代「解決了什麼／提出什麼」以及「留下什麼問題或轉折，自然引出下一步」。
2. **跨篇方法與目標差異**：用對照表呈現各篇的主要目的、核心方法／干預方式，以及與前後篇或不同路線的差異（例如輸出端向量與檢索、對比學習與分佈調整、Causal 模型轉雙向編碼、內部表示讀取與控制、稀疏特徵分解、單一方向干預與權重正交化）。
3. **新手教學講解順序**：按零基礎學習者的理解先後排列步驟，說明每階段要講什麼、釐清哪些容易混淆的概念。
4. **侷限性與防過度宣稱提醒**：彙整各篇限制與邊界條件（如算力／上下文長度成本、線性假設與干預副作用、重建 loss 與泛化邊界、啟發式抽取與開源模型範圍），避免在後續簡報或解說中把方法描述得過度萬能。
5. **可溯源標記**：每一段跨篇歸納、轉折或比較列都必須標註對應的 `[檔名.md]`，且只使用 `notes/*.md` 既有內容。

## 4. 確定性檢查項目（由 `scripts/check_wiki.py` 驗證）
- `wiki/index.md` 由腳本同步產生，收錄 `notes/` 中的目標條目並維持一致欄位。
- `wiki/synthesis.md` 中所有 `[... .md]` 引用皆對應真實存在的筆記檔名，且涵蓋所有納入的筆記。
- 檢查是否有未填寫的佔位符（如 `TODO`、`FIXME`、`待補充`）、計數詞矛盾或格式損壞的 Markdown 表格。

## 5. 如何執行腳本
在更新 `wiki/synthesis.md`（或新增／修改 `notes/*.md`）後，於專案根目錄執行確定性檢查與索引生成腳本：
- **執行指令**：`python scripts/check_wiki.py`
- **腳本職責**：自動掃描 `notes/` 並更新 `wiki/index.md`（與索引清單／檢查紀錄），同時驗證 `wiki/synthesis.md` 的引用、覆蓋率與格式。

## 6. 成功與失敗判定標準
- **成功（PASS）**：
  - `wiki/index.md` 已依最新 `notes/*.md` 同步更新。
  - `wiki/synthesis.md` 中所有 `[... .md]` 引用皆存在於 `notes/`，且無拼寫錯誤。
  - `notes/` 中的每一篇筆記在 `wiki/synthesis.md` 中皆至少被引用一次。
  - 無未完成佔位符（如 `TODO`、`FIXME`、`待補充`）或明顯矛盾的計數詞。
- **警告（WARN，可視情況處理）**：
  - 出現非致命的格式或數量詞提示（例如新增論文後，段落中的「前N篇」計數詞尚未調整）。建議修正後再重跑一次以達乾淨的 `PASS`。
- **失敗（FAIL）**：
  - `wiki/synthesis.md` 出現不存在或拼錯的 `[... .md]` 檔名。
  - 有筆記未被 `wiki/synthesis.md` 引用到，或缺少必要章節、表格結構損壞。

## 7. 失敗或警告後的處理流程（Loop / 重試）
當 `scripts/check_wiki.py` 出現 `FAIL`（或需要消除的 `WARN`）時，依下列步驟修正並重跑，直到通過為止：
1. **定位問題**：查看腳本輸出的錯誤／警告項目，確認是「引用檔名錯誤」、「漏引用某篇筆記」、「章節／表格格式有誤」或「計數詞不一致」。
2. **修正來源或 `synthesis.md`**：
   - 若引用檔名拼錯或指向不存在的 `.md`，更正為 `notes/` 中實際存在的檔名。
   - 若有筆記漏引用，回到 `wiki/synthesis.md` 補上對應的脈絡段落、比較列、教學順序或侷限提醒與引用標記。
   - 若出現佔位符或計數詞矛盾，將對應文字補齊或更新。
3. **重新執行驗證**：再次執行 `python scripts/check_wiki.py`，確認 `wiki/index.md` 同步且檢查結果轉為 `PASS`。
