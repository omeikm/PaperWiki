# Agent Specification: Wiki index & synthesis updator (Wiki Agent)

## 1. 職責範圍
當新增論文 PDF、更新 `notes/*.md` 或重新建置網站時，負責同步維護 `wiki/` 知識庫。
- `notes/*.md`：單篇論文的完整結構化筆記（MetaData、摘要、方法、實驗、限制、省思）。
- `wiki/index.md`：知識庫總索引，列出所有收錄條目、年份、核心定位與檔案路徑。
- `wiki/synthesis.md`：跨篇脈絡彙整，包含主線演進、方法與目標差異、新手教學順序，以及侷限性與防過度宣稱提醒。

## 2. 更新流程
1. **盤點變更**：檢視 `notes/` 中新增或更新的 `.md` 檔案（例如 `2019-reimers-sbert.md`、`2021-gao-simcse.md`、`2023-zou-repe.md`、`2024-arditi-refusal.md`、`2024-behnamghader-llm2vec.md`）。
2. **更新 `wiki/index.md`**：新增或更新條目列，確保欄位格式統一、路徑正確。
3. **更新 `wiki/synthesis.md`**：
   - 在「主線演進脈絡」補入或調整銜接段落與轉折說明。
   - 在「跨篇方法與目標差異」更新比較列。
   - 在「新手教學講解順序」確認講解先後與學習重點是否合理。
   - 在「侷限性與防過度宣稱提醒」補齊該篇的限制與邊界條件。
4. **執行確定性驗證**：跑檢查腳本驗證索引、連結與引用標記。

## 3. 撰寫與溯源規則
- **嚴格忠於來源**：只使用 `notes/*.md` 已記載的資訊，不自行推測實驗數字或宣稱未驗證的效果。
- **強制標註來源**：`wiki/synthesis.md` 的每個要點、轉折或比較列都必須附上 `[檔名.md]`（多篇來源可並列如 `[2024-behnamghader-llm2vec.md][2023-zou-repe.md]`）。
- **維持分工清晰**：避免把單篇細節整篇搬進 `synthesis.md`，重點放在跨篇關聯與脈絡。

## 4. 確定性檢查項目（交由程式/規則驗證）
- `wiki/index.md` 所列檔案皆存在於 `notes/`，且 `notes/` 中的目標條目皆已列入 `wiki/index.md`。
- `wiki/synthesis.md` 中所有 `[... .md]` 引用皆對應真實存在的筆記檔名。
- 檢查是否有未填寫的佔位符（如 `TODO`、`待補充`）或格式損壞的 Markdown 表格。

## `synthesis.md` 撰寫要點
撰寫或更新 `wiki/synthesis.md` 時，應圍繞「跨篇關聯」而非單篇摘要重述，並遵守以下要點[cite: 6, 7]：
1. **主線演進脈絡（問題驅動）**：以由淺入深的段落串起各篇脈絡，每段交代「解決了什麼／提出什麼」以及「留下什麼問題或轉折，自然引出下一步」[cite: 7]。
2. **跨篇方法與目標差異**：用對照表呈現各篇的主要目的、核心方法／干預方式，以及與前後篇或不同路線的差異（例如輸出端向量與檢索、對比學習與分佈調整、Causal 模型轉雙向編碼、內部表示讀取與控制、單一方向干預與權重正交化）[cite: 6, 7]。
3. **新手教學講解順序**：按零基礎學習者的理解先後排列步驟，說明每階段要講什麼、釐清哪些容易混淆的概念[cite: 6, 7]。
4. **侷限性與防過度宣稱提醒**：彙整各篇限制與邊界條件（如算力／上下文長度成本、線性假設與干預副作用、啟發式抽取與開源模型範圍），避免在後續簡報或解說中把方法描述得過度萬能[cite: 6, 7]。
5. **可溯源標記**：每一段跨篇歸納、轉折或比較列都必須標註對應的 `[檔名.md]`，且只使用 `notes/*.md` 既有內容。
