How to use and interpret activation patching

如何使用與解讀 Activation Patching

Authors & AffiliationStefan Heimersheim, Neel Nanda
Venue & YeararXiv 2024
Date Added2026-11-20
Last Modified2026-11-20

核心價值：總結 Activation Patching 的實務方法與解讀陷阱，指出如何從因果干預推論 circuit，而不把單一 patch 結果過度解讀。

主要貢獻：

  1. 比較 exploratory／confirmatory patching 與多種 patch target 粒度。
  2. 分析 denoising、noising、ablation 與 Gaussian noise patching 的差異。
  3. 比較 logit、logprob、probability、accuracy 與 KL divergence 等 metric。

研究痛點：Activation patching 有多種名稱與變體；heatmap 或 single metric 很容易誤讀必要性、充分性與 circuit minimality。

核心洞察 (Key Insight)：Patching 可用另一個 prompt run 的 activation 替換指定 activation，以精確控制哪些 prompt fact 發生變化，但結果只對特定 prompt distribution 有效。

  1. 選 clean/source 與 corrupt/destination prompt，保存 source activations。
  2. 在 destination run overwrite residual stream、MLP、attention head、neuron 或 SAE feature。
  3. Denoising：由 clean patch 修復 corrupt run，測 sufficient restoration。
  4. Noising：由 corrupt patch破壞 clean run，測 necessary maintenance。
  5. 確認 circuit 時可用 path patching 與多層 component patching。

評估內容：以 factual recall、IOI、AND／OR circuit 與 toy Nobel Prize circuit 說明 patching 巡讀方式，以及多種 metrics 的差異。

關鍵發現：

  • Denoising 與 noising 不互為對稱，分別測充分性與必要性。
  • 窄 prompt variation 適合 exploratory patching，確認 circuit 則需較廣 prompt distribution。
  • 連續、較線性的 logit difference 或 logprob difference 通常更適合 exploratory patching。
  • Accuracy／probability 可能受 threshold 或 exponential transform 影響而失去部分變化。

侷限性：Patching 結果高度依賴 prompt distribution；positive result 不代表找到最小 circuit；AND／OR、backup heads、negative components 與 metric choice 都會影響解讀。

未來展望：結合多組 prompt、path patching、causal scrubbing 與多種 metrics 更嚴格驗證 circuit；持續處理 backup behavior 與 negative components。

涵蓋 Causal Tracing、Interchange Intervention、Resample Ablation、Causal Mediation Analysis、Causal Scrubbing 與 attribution patching。

本文不是新的 steering 或 feature extraction 方法，而是提供 activation patching 與 circuit evidence 的實務解讀規範。

研究省思：可建立「控制 prompt difference → 選 patch target → 選 metric → 解讀 sufficiency/necessity」的標準流程。

研究切入點：讀任何 patching 結果時，應同步檢查 denoising／noising、prompt distribution、metric 與 backup behavior。
